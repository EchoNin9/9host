Section 01 · Locked Requirements

All Confirmed Decisions (Q1–Q8)

Every architectural choice below is locked and reflected in the repository specification (`GLOSSARY.md`, `docs/adr/`, `docs/SPEC.md`, `TASKS.md`, and `docs/UNATTENDED_ORCHESTRATION.md`).

Q1 & Q5 · Custom Domains LOCKED · OPTION B2

Cloudflare for SaaS on echo9.net (100 Domains Free)

  • Why Option B2 wins: End users at ClouDNS or any registrar simply add CNAME -> proxy.echo9.net. Zero Cloudflare account or Worker setup required by end users.
  • Verified Cloudflare Pricing: First 100 Custom Hostnames are $0/mo on Cloudflare Free plan ($0.10/mo per additional hostname after 100).
  • Verified Host-Header Solution ($0/mo): Because CloudFront rejects unknown Host headers and Cloudflare Host Header Override is Enterprise-only, one 12-line Cloudflare Worker on your echo9.net account (Free tier: 100,000 req/day free) acts as the Fallback Origin on proxy.echo9.net, forwarding requests to CloudFront with X-Forwarded-Host: <custom-domain>.
  • Bare Domain Landing Page: Replace the old echo9.net -> tools.e9.cx redirect so echo9.net / www.echo9.net serves a clean 9host landing page while proxy.echo9.net handles custom domains.
  • Delete AWS ACM Bloat: Delete infra/lambda_acm.tf, infra/lambda_acm_handler/, and CloudFront Alias mutations.
Q2 · Edge Routing & Visitor Landing LOCKED · SPLIT NOW

Split Admin SPA (app/stage) from Public Sites (*.echo9.net)

  • Admin Control Plane: app.echo9.net (prod) and stage.echo9.net (staging) serve the React Admin/Superadmin SPA exclusively.
  • Public Sites Plane: *.echo9.net points its default behavior (/*) directly to S3-9host-sites with cf-site-content.js + CloudFront KeyValueStore (KVS).
  • Fixes Visitor Landing Bug: Visiting https://<slug>.echo9.net/ or https://myband.com/ resolves host -> {tenant}/{site_id} at the CloudFront edge in <1ms and serves static HTML at /.
  • Deletes Redirect Hop: Removes RootRoute in App.tsx and deletes api/default_site_handler.py (zero Lambda or DynamoDB calls on public site visits).
Q3 · Domain Onboarding Workflow LOCKED · ONE-BY-ONE

Add & Customize Sites Individually from ClouDNS / Any DNS

  • No Bulk "Parked Banner" Tool: You will add your non-critical domains one by one from ClouDNS or other registrars and customize each into a real site using templates and the content editor.
  • Root-Relative Template Links: Published sites render clean root-relative URLs (/, /blog/, /events/, /media/...) instead of /site/{tenant}/{site_id}/.
Q4 & Q6 · Billing & Tiers in MVP LOCKED · OPTION A (FLAGGED)

Feature-Flag Billing Hidden in MVP (`VITE_ENABLE_BILLING=false`)

  • Clean MVP UI: Gate the Billing tab, pricing cards, and upgrade banners behind VITE_ENABLE_BILLING=false (frontend) and BILLING_ENABLED=false (backend) so billing UI is completely hidden during MVP.
  • Fix Underlying Stripe Bugs Now: We still fix the is_payable_tier("FREE") checkout blocker in api/billing_handler.py and the VIP tier overwrite bug in api/stripe_webhook_handler.py so flipping the flag to true later requires zero code changes.
Q7 · Hybrid Auth Architecture LOCKED · KEEP & HARDEN

Cognito for Tenant Admins + Self-Managed TUSER / Roles / Groups

  • Assessment — Yes, This Is a Good Design: Tying Tenant Admins and Superadmins to AWS Cognito gives you MFA, Passkeys, and future 3rd-party OIDC/SAML IdP federation for account owners, while allowing Tenant Admins to manage lightweight site users (TUSER), custom ROLEs, and GROUPs in DynamoDB for $0 MAU cost and full flexibility.
  • Full Cognito Footprint Preserved: Nothing in Cognito is reduced.
  • What We Fix: Consolidate Cognito JWKS local verification + TUSER HMAC verification + Superadmin X-Impersonate-Tenant resolution inside RequestContext, and separate access_token from site_token in the frontend ApiClient.
Q8 & Model Strategy · Deepening & Opus LOCKED · OPUS ORCHESTRATOR

All 5 Deepening Modules + Clean Packaging + Opus Execution

  • 5 Deep Modules Approved: EdgeHostRouter, RequestContext, TenantStore, SiteCompiler, and ApiClient + shared tenant/admin views.
  • Clean `api/` Tree: Move vendored third-party wheels (stripe/, jwt/, bcrypt/, requests/) out of git source into the build/packaging step and add pytest + vitest suites.
  • Preserve Argon Quota: The unattended runbook is configured for Claude Opus 4.6 (or Sonnet) as Commander/Subagents so you do not burn your weekly Argon limit.

Section 02 · Candidate 01 · Edge Host Router & Cloudflare for SaaS (Option B2)

Site & Custom Domain Routing: Broken Flow vs. Split Edge + Cloudflare for SaaS

Left: Current single-distribution setup where visiting <slug>.echo9.net/ boots the React SPA, invokes Lambda + DynamoDB, and redirects to /site/{tenant}/{id}/. Right: Confirmed split architecture with app/stage.echo9.net for Admin SPA, (www.)echo9.net for Landing Page, and *.echo9.net + proxy.echo9.net (Cloudflare for SaaS) resolving via CloudFront KVS in <1ms.

HOW OPTION B2 WORKS END-TO-END

1. User Adds CNAME at ClouDNS

  • User adds myband.com in 9host UI.
  • 9host calls Cloudflare Custom Hostnames API (POST /zones/{id}/custom_hostnames) and returns the TXT validation record + CNAME -> proxy.echo9.net.
  • Cloudflare automatically issues and renews the SSL certificate for myband.com.

SOLVING CLOUDFRONT HOST HEADER

2. Fallback Worker on echo9.net

  • A single 12-line Cloudflare Worker on your echo9.net Cloudflare zone routes custom hostname requests to https://sites-origin.echo9.net with header X-Forwarded-Host: myband.com.
  • Included in Cloudflare Workers Free plan (100,000 req/day free) + 100 Custom Hostnames free ($0/mo total).

SUB-MILLISECOND S3 RESOLUTION

3. CloudFront KVS Edge Lookup

  • cf-site-content.js reads x-forwarded-host || host, looks up {tenant}/{site_id} in CloudFront KVS, and rewrites request.uri to /{tenant}/{site_id}/live/index.html.
  • Also supports echo9.net / www.echo9.net landing page!
